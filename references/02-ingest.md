# 02 · 取回与解包

把 PDF 变成**可检索、可核对、可引用**的原料。这一步是后面所有"回原文核"的前提。

产物：全文文本 + 节标题清单 + `figures/` 插图。

---

## 一、先确认手上是什么

| 检查 | 命令 | 不合格怎么办 |
|---|---|---|
| 是不是真 PDF | `head -c 5 x.pdf` → 应为 `%PDF-` | 是 HTML 错误页，重下 |
| 是否下载完整 | `tail -c 32 x.pdf` 含 `%%EOF` | 重下 |
| 体积是否正常 | > 10 KB | 太小说明是空文件或跳转页 |
| **有没有文本层** | `plens.py text` 抽出来是否为空/乱码 | 见下节 |

**扫描版 PDF（纯图像）不要用 OCR 去猜数字。** 论文里的表格数字差一位就改变结论，OCR 错一个小数点会毁掉整篇总结。这种情况直接告诉用户：需要带文本层的版本。

---

## 二、抽全文

```bash
python <skill>/scripts/plens.py text paper.pdf -o _full.txt
python <skill>/scripts/plens.py text paper.pdf -o _p7-10.txt --pages 7-10
```

输出每页带 `===== PDF page N =====` 分隔头，便于按页定位。

**为什么必须抽文本，而不是"直接读 PDF"：**

- 读 PDF 的工具往往只能给到渲染后的文本流，长文会被截断、跨页表格会错位。
- grep 一个 2000 行的文本文件是秒级的；逐页 Read 一篇 40 页论文要十几轮，且容易漏。
- **核数需要精确字符串匹配**：`0.5000` 和 `0.5` 在 grep 里是不同的东西，在视觉上是同一个东西。

---

## 三、先捞节标题，再读内容（最容易省掉、也最容易出事的一步）

```bash
python <skill>/scripts/plens.py toc paper.pdf
```

输出带层级和页码的标题清单，例如：

```
[1] 1  Introduction                                  p.1
[2] 2  Method                                        p.3
[2]   2.1  Tokenizer                                 p.3
[1] A  Implementation Details                        p.11
[1] B  Additional Results                            p.13
```

### 为什么这一步不能跳

分段读 PDF 时，每段之间会有**窗口缝隙**。附录标题恰好落在缝隙里时，你会得出"这篇没有讨论局限"这种错误结论——而实际上 §Limitations 就在附录 B。

**实测教训**：曾有一篇论文，正文里的上下文长度写 500，附录 A.2 写 100。只看正文会漏掉这个内部矛盾；而这个矛盾直接决定实验能否复现。

所以：**核结构必须先 grep 全量标题，禁止靠分段读拼凑。**

### 抽出来的文本怎么用

| 目的 | 做法 |
|---|---|
| 核某个数值 | `grep -n "0.6772" _full.txt` |
| 找某节在哪 | `grep -n "^[A-Z] \|^[0-9]\+ " _full.txt` |
| 确认有无附录 | 看 `toc` 输出里有没有字母编号的条目 |
| 找代码链接 | `grep -in "github\|code is available" _full.txt` |

## 四、抽图

```bash
python <skill>/scripts/plens.py figures paper.pdf -o figures/
```

做法：定位 `Figure N:` 题注 → 向上取最近的矢量/图像区域 → 向下取到题注底部 → 按倍数渲染成 PNG。

**抽完必须逐张目检。** 自动裁剪会犯两类错：

| 症状 | 处理 |
|---|---|
| 图里混进了正文段落 | 收紧上边界过滤条件（高度阈值） |
| 子图被切掉一半 | 放宽边界，或提高 `--scale` |
| 同页多图粘连 | 检查题注解析，确认按 y 坐标分割正确 |
| 图注编号与正文不符 | 以题注为准，在产物里注明 |

常见坑：

- **同一页有两张图**时，第二张的上边界容易吃到第一张的题注。
- **跨页大图**（如架构图占两页）抽不完整 → 手工截，标"人工截取"。
- 页眉页脚里的 `Figure` 字样会被误判成题注 → 排除页眉区域。

抽图的用途不只是插图：**架构图往往比正文更准确地表达数据流**，精读时应该先看图再看方法节。

## 五、后端依赖

`plens.py` 自动选后端：

| 后端 | 能做什么 | 装法 |
|---|---|---|
| **PyMuPDF**（推荐） | 抽文本 + **抽图** + 坐标信息 | `pip install pymupdf` |
| **pypdf** | 只能抽文本 | `pip install pypdf` |
| `pdftotext`（poppler） | 命令行，`-layout` 保留版式，表格友好 | 系统包管理器 |

抽图必须 PyMuPDF。只有 pypdf 时 `figures` 会明确报错，不会静默产出空目录。

## 六、文本层的已知缺陷

| 现象 | 原因 | 应对 |
|---|---|---|
| 附录表格数字缺失 | PDF 里图表是 form XObject，超出调用上限 | 人工翻 PDF 核对硬件/成本类信息 |
| 公式变成乱码 | 数学字体无 Unicode 映射 | 以图像为准，手动录入 LaTeX |
| 连字符断词 | 排版换行 | grep 时把关键词拆开试：`cross-\nsubject` |
| 双栏顺序错乱 | 抽取按坐标排序 | 按页抽，逐页看上下文 |
| **表格列错位** | 表头与数据行拆成不同文本块，列顺序会串 | **回看 PDF 确认哪列是哪列**，再填表 |

### ⚠️ 表格数值不能盲抄

文本层能给你**准确的数字**，但不保证给你**正确的列**。抽出来常常是这样：

```
GLFA       ECCV 24   1   0.840±0.03  0.209±0.02  0.742±0.49 ...
MindBridge CVPR 24   1   0.821±0.03  0.206±0.02  0.754±0.42 ...
MindCross  Ours      1   0.830±0.03  0.210±0.03  0.762±0.34 ...
```

六个数并排摆着，但**哪个数是哪个指标，这段文本并不告诉你**——列头可能在上面几行，也可能在另一页。

正确顺序：

1. 抽文本，拿到**准确数值**
2. 打开 PDF 盯着该表，确认**列头顺序**和**哪一格是加粗的最优值**
3. 两边对齐后再填进产物

只做第 1 步就填表，会把「语义指标」和「像素指标」写反——而且成品看起来毫无破绽。

## 七、落盘位置

| 文件 | 位置 | 是否保留 |
|---|---|---|
| `<arxiv-id>v<n>.pdf` | 论文目录 | ✅ 永久 |
| `figures/figNN.png` | 论文目录 | ✅ 永久（Full 档要用） |
| `_full.txt` / `_pN.txt` | 论文目录 或 系统临时目录 | ⚠️ 用完移入 `_trash_<日期>/` |
| `info.md` | 论文目录 | ✅ 永久 |

临时文本**用 `mv` 归档，不要 `rm`**——用户的数据由用户自己决定删不删。
