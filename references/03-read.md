# 03 · 精读产稿（Standard 档核心）

目标：产出**讲解级**的中文精读稿——读者看完能向别人复述这篇论文怎么做的，而不是只记住结论。

判据很直白：**如果读者看完觉得"不如直接看原文"，这份稿子就是失败的。**

产物：`<短名>_中文精读.md`（必需）、`<短名>_精读_图文版.html`（Full 档）。

---

## 一、两种起点，别搞混

| 起点 | 特征 | 做法 |
|---|---|---|
| **A. 已有译稿** | 目录里有机器翻译导出的 md | **只修不重写**：补缺节、修表格、补公式、修脚注 |
| **B. 没有译稿** | 只有 PDF | 直接从原文写中文精读（跳过修复步骤） |

判断依据是文件在不在，不是"有没有时间"。

### 起点 A：修译稿的典型缺陷

机器翻译稿几乎必然带这几类毛病，逐条查：

| 缺陷 | 表现 | 修法 |
|---|---|---|
| **整节被压平/省略** | 方法节只剩一段话 | 按原文补回小节，公式恢复原编号 |
| **表格变占位符** | "（此处省略表格内容）" | 用 `plens.py text --pages` 抽该页文本，逐格抄成 GFM 表 |
| **脚注粘进正文** | 句子中间突然冒出 `1` 或作者名 | 改为 `<sup>n</sup>` + 段后引用块 |
| **图表交叉引用错** | 正文说"表 7(b)"实际是图 7(b) | 修正并加括注说明改了什么 |
| **数值被改写** | `0.6772` → `0.68` | **一律回原文核**，这是最危险的一类 |
| **术语前后不一** | 同一概念三种译法 | 统一，并在术语表里定死 |

**修译稿不是校对文字，是修复信息损失。** 把被删掉的公式和表格补回来是主要工作量。

### 起点 B：直接写

没有译稿时不要试图"生成一篇完整翻译"（见下面的版权边界），而是：

1. 用 `plens.py toc` 拿到完整结构
2. 按节读原文，写**中文译述 + 你的解释**
3. 图表、公式、数值按事实照录

---

## 二、版权边界（必须遵守）

允许：

- 逐节**忠实译述**（用自己的话概括每一节在说什么）
- 照录**公式、数值、表格数据、图表**——这些是事实性内容
- 编辑用户自己提供的译稿

不允许：

- 输出整篇逐字对应翻译（等于复制衍生作品）
- 把论文 PDF 或大段原文重新分发

产出的定位是**学习笔记**，不是译作。HTML 模板里的说明段已经写明这一点，不要删。

---

## 三、精读 md 的骨架

```markdown
# <中文标题>：<副标题> —— 中文精读
> 原文（arXiv:<id>，<venue>）逐节译述 + 图表/公式/数据整理；逐字原文以同目录 PDF 为准。插图见 figures/。

## 0. 论文元信息
   表格：标题 / 作者 / 单位 / 发表 / arXiv / 代码 / 数据规模 / 模型规模 / 评测广度

## 摘要
   忠实译述；核心挑战与对策加粗

## 1. 引言
### 1.1 背景与动机          bullet
### 1.2 现有工作的缺口       编号列表；嵌动机图（通常 fig01）
### 1.3 思路与贡献          bullet

## 2. 方法
### 2.x 各小节              公式 $$... \quad (n)$$ 保留原编号；嵌架构图

## 3. 实验
### 3.1 设置                数据清洗流水线、规模、超参要点
### 3.2 数据集与基线        数据集总表 + 基线/指标说明
### 3.3 主结果              关键指标加粗，给出 vs 最强基线的差
### 3.4 消融与分析          每条一句结论 + 图/表号

## 4. 结论
   含局限与未来方向

## 附录要点速览
   按附录字母 bullet，一条一句

## 术语中英对照表
   两列 GFM 表，10–15 条

## 精读小结
   编号 4–6 条：核心洞察 / 与同类路线的差异 / 工程亮点 / 对本方向的意义 / 可复现性
```

## 四、"讲解级"到底要求什么

这是本阶段唯一的质量门槛。**方法节和实验节必须做到下面六条**，其他节可以简写。

### 1. 符号与维度速查表

方法节开头放一张表，把后文要用的每个符号定死：

| 符号 | 含义 | 取值 / 形状 | 出处 |
|---|---|---|---|
| `B` | batch size | 256（超参表 A.1） | 附录 A.1 |
| `L` | 序列长度 | 30–500 随机采样 | §4.1 |

**形状要写到能自己算一遍的程度**，不是只写"是一个矩阵"。

### 2. 端到端数据流

用一段话把形状从头走到尾：

> 输入 `(B, C, T)` → 分块得 `(B, N, P)`，其中 `N = T/P` → 线性投影 `(B, N, d)` → 加位置编码 → 12 层 transformer 保持 `(B, N, d)` → 池化 `(B, d)` → 分类头 `(B, K)`

读者能照着这段心算出每个中间张量的形状，才算讲清。

### 3. 每个模块写齐四件套

| 项 | 要回答的问题 |
|---|---|
| **输入** | 形状是什么、代表什么 |
| **处理** | 逐步做了什么运算 |
| **输出** | 形状是什么、代表什么 |
| **为什么这样设计** | 解决了什么困难；如果反直觉，特别标出来 |

反直觉设计尤其要讲，例如"线性原始路径专职当重建目标"——这类设计往往正是论文的关键。

### 4. token 与序列轴

如果论文有 token 概念（transformer 类都有）：

- **一个 token 是什么**？从哪一步切出来的？
- **序列轴对应什么**？时间？空间？样本？**这条最容易被跳过，也最容易被误解。**
- 引附录伪代码或公式编号作佐证，不要凭印象。

### 5. 预训练/辅助任务的机制

如果论文有自监督或 pretext 任务：

- 掩码/扰动的对象是什么、比例多少
- 原位替换还是移除
- 各重建头的目标、目标值从哪来（**注意不对称目标**）
- 这个设计想换到下游的什么能力

### 6. 公式给"逐项读法"和直觉

每个重要公式：符号逐个念一遍 → 整体在算什么 → 为什么需要它 → 有没有消融证明它有用。

例：负载均衡损失为什么需要？因为不加的话专家会坍缩到少数几个。这类"它防什么坏情况"的说明比公式推导有用。

### 7. 实验节给指标直觉与读表法

- 每个指标一句："它测什么能力 / 它防什么作弊"
- 表格给读法：分几块、加粗范围是什么、哪一列是关键
- 主结果必须和**最强基线**比，不是和最弱基线比

## 五、排版约定

- **数值逐格抄自文本层 dump**，不用目视读图（密集表格看着读必错数位）。
- 表格用 GFM；**最优行整行加粗**；表下加一行说明：`（均值 ± 标准差，N 个随机种子；监控指标：X）`。
- 公式：`$$<latex> \quad (n)$$`，编号与原文一致。**不要重新编号。**
- 插图：`![图 N：中文题注](figures/figNN.png)`，放在**首次讨论它的地方**，不要堆到文末。
- 脚注：正文 `<sup>n</sup>`，段后 `> <sup>n</sup> ...` 还原。

## 六、图文版 HTML（Full 档）

以 `<skill>/assets/jingdu-template.html` 为骨架，CSS 已内置，**不要改样式**——统一外观是为了多篇之间可对照。

结构：`header.doc` → `nav.toc`（锚点目录）→ `main`（`h2[id]` 分节）→ `footer.doc`。

| 元素 | 写法 |
|---|---|
| 公式 | `<div class="eq"><span>Unicode 数学式</span><span class="no">(n)</span></div>`，**不引 MathJax**（离线可用） |
| 关键数值 | `<span class="key">0.6772</span>` 高亮 |
| 插图 | `<figure><img src="figures/figNN.png" alt="图 N"><figcaption><b>图 N</b>：题注</figcaption></figure>` |

**所有图都要嵌**，包括附录里的——读者不该为了看一眼附录图去翻 PDF。

完成后必须校验：

```bash
python <skill>/scripts/plens.py check <html>
```

期望 `RESULT OK`。它检查三件事：标签闭合、图片路径存在、锚点可达。

**不要用浏览器逐页点开验证**——慢且不可靠，校验脚本覆盖的是同一批问题。

## 八、完成汇报

给四行就够：

```
精读稿：<路径>（N 字）
插图：figures/ 共 N 张（已目检）
HTML：<路径> — RESULT OK
疑点：<未核实的数值 / 论文内部矛盾，若有>
```

然后**停下来**。下一步是用户自己读。不要说"要不要我接着总结"——见 `04-summarize.md` 的触发条件。

## 九、常见失败模式

| 症状 | 根因 | 修法 |
|---|---|---|
| 读者说"讲得太少，不如看原文" | 只有译述，没有解释 | 补符号表、数据流、四件套 |
| 方法节读不懂 | 缺形状信息 | 每个模块都标输入/输出形状 |
| 公式看不懂 | 只抄了公式 | 加逐项读法和"它防什么" |
| 消融看了没印象 | 只列数字 | 每条消融一句结论 + 说明它证明了什么 |
| HTML 图裂了 | 路径不对或图没抽全 | 跑 `check`，看 `missing_detail` |
| 术语表像凑数 | 只列了名词 | 每条补"和相近概念的区别" |
