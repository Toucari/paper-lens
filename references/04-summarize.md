# 04 · 八节结构化总结

目标：每篇产出一份**自足、可独立分发、可横向对照**的总结。

"自足"的意思是：别人只拿到这一份文件，也能知道这篇论文是什么、强在哪、弱在哪、能不能用、该引用它的哪句话。

---

## 一、触发条件（硬性）

**必须等用户明确确认读完**（"读完了""我看完了""行了"之类）。

以下都不算：

- 精读稿写完了
- 用户说"先放着吧"
- 这一批要收尾了
- 用户问了很多问题（问得多说明还在读）

**为什么这么严**：八节总结的第①节是问答历史，第⑧节是价值评级。这两节的内容都来自**用户自己的阅读过程**。用户没读，这两节只能是编的——那样的总结看着完整，实际没有任何判断价值。

---

## 二、八节格式（编号和名称不得改）

| 节 | 名称 | 写什么 | 硬要求 |
|---|---|---|---|
| 头 | **一句话定位** | 一段话说清这篇是什么、最硬的结论 | 非八节内容，置于文首 |
| 一 | **问答历史** | 阅读期用户问过的问题 + 当轮结论 | 表格 `# / 问题 / 结论`；**引原问题措辞**；无则如实写"无" |
| 二 | **论文主要内容** | 立论 / 方法流程 / 关键参数 / 主结果 / 消融 | 讲清端到端流程与关键数值，数值须核过 |
| 三 | **主要亮点** | 相对同类工作**增量在哪** | 每条带证据锚点；与"论文自声称的贡献"区分 |
| 四 | **Research Gap** | **该做的没做** | 编号 G1–Gn；每条注明"哪一节本该给而没给" |
| 五 | **可引用的部分** | 引用口径 | **强制三行表**：`引结论 / 搬模块 / 当靶子`，每行分「可以引 / 不要引」 |
| 六 | **存在的问题** | **做了但不干净/不对** | 表格 `问题 / 类型 / 证据锚点 / 影响`；每行落到式号/表号/代码行 |
| 七 | **有价值的点** | **对我有什么用 → 怎么用** | 强制两列；按 ★★★ / ★★ / ★ 排；附成本 |
| 八 | **总体价值评级** | 预判档位 A/B/C + 理由 | 表格：档位 / 一句话理由 / 最强证据 / 最大短板 / 引用口径 / 是否值得深入 |
| 附 | **事实核验状态** | 哪些已核、哪些是推断 | 表格，逐条 ✅ / ⚠️ |

第⑤节的三行表是**引用口径**，不是摘要。它的用途是：三个月后你要引用这篇论文时，能立刻知道哪句话能引、哪个模块能搬、哪里可以当反例——不用重读全文。

---

## 三、问答历史：四种来源，处理方式不同

阅读期的问答不一定都发生在你这里。按实际发生地分四类：

| 情形 | 标注要求 | 额外动作 |
|---|---|---|
| ① 全程本端答疑 | 不必标注 | 无 |
| ② **全程第三方**（另一个模型 / 另一个助手） | **必须写模型名**，并声明"本端未参与答疑，只做核数与归档" | **数值回原文抽查** |
| ③ **双来源**（一部分问这里、一部分问别处） | 表格加**「来源」列**，逐条标明 | 抽查第三方给出的数值 |
| ④ 无问答（自行阅读） | 写「本次精读无问答记录（直接阅读）」 | **不编** |

### 第三方转录的四条硬要求

1. **保留原问题措辞**——不许改写，不许概括成"读者关注了…"。原问题的问法本身就是判断线索：他卡在哪、误以为是什么。
2. **多次转录 → 取并集，逐条标「仅见第一份 / 第二份」**。不许因为后一份更完整就丢掉前一份独有的问题。两份对同一问题给出不同回答时，以原文为准并注明分歧。
3. **只有回答、原问题缺失时**：单列一行注明「原问题未含在转录中」，**不许虚构问题**。
4. **表后必须加「数值抽查」小节**：把转录里出现的数值逐条与原文（表号 / 式号 / 行号）核对，标 ✅ / ⚠️。

**未核实的数值不得进入 §二 / §六 / §八**——只能留在抽查小节里并标 ⚠️。

### 为什么这条规则值得认真执行

两个真实情形：

- 一份第三方转录说"某模型在某数据集上等于随机猜测"。回原文查主表，Balanced Accuracy **恰好是 0.5000**——这条成立。不复核的话，会以为对方在夸大其词。
- 另一份说"加入结构约束提升了性能"。回原文看，主指标 Top-5 反而**降了 0.4**，只有辅助指标涨了——这不是谎报，是选择性陈述。不复核就会把内部矛盾漏掉。

问答历史的价值不在"看起来有人读过"，而在**记录你当时到底卡在哪**。半年后重读这篇论文，这份记录比总结正文更有用。

## 四、Gap 与问题：最容易混的一对

| 例子 | 归类 | 理由 |
|---|---|---|
| 没有任何生成式下游评测 | **Gap** | 该做而没做 |
| 消融只在 4 个数据集做，却宣称覆盖 12 个 | **问题** | 做了但覆盖不足 |
| 无零信号负对照、无多次运行方差 | **Gap** | 协议该补没补 |
| 预训练用了下游评测数据却没声明剔除 | **问题** | 做了但不干净 |
| 立论用一个假设但从未测量验证 | **问题** | 论证不足 |

判不准时问自己：**"论文没做这件事"，还是"论文做了但做得不对"？**

写 Gap 之前，必须先用 `plens.py toc` 确认全文结构——**Limitations / Future Work 章节很可能在附录里**，而论文自己列出的局限往往不是最重要的 Gap。你的 Gap 应该来自"这篇论文的逻辑链上缺了哪一环"，不是抄它的 limitations。

## 五、评级：只给档，不给分

本阶段只出 **A / B / C 预判档位**，不给五维加权分。

原因很实际：两套尺度同时维护必然打架。分数在 `05-evaluate.md` 里算，那里有锚点和校准机制。

| 档 | 含义（粗判） |
|---|---|
| **A** | 证据可信 + 工具可用，结论可以放心引用，代码能跑 |
| **B** | 有真价值，但引用时要加限定语 |
| **C** | 工具或结论至少一项不可用，只作反面教材或纯工程件来源 |

**评级权威在单篇文件 §八。** 轮次总结、批次表只能引用指针，不能另写一份评级。

## 六、执行流程

### 第 0 步：备素材

| 素材 | 首选来源 |
|---|---|
| 问答历史 | 本次阅读期的提问记录 |
| 主要内容 / 亮点 / 数值 | 上游精读稿；**数值回原文核** |
| Gap / 问题 | 精读稿 + `plens.py toc` + 全文 grep |
| 历史口径 | `$PL_ROOT/ledger/registry.md`（若存在） |

### 第 1 步：逐节写

按第二节的表逐节产出。**骨架直接复制 `<skill>/assets/summary-template.md`**——它的节序、表格列、自查清单都已经对齐本文档，不要自己另起格式（格式一乱就无法横向对照）。数值一律回原文。

### 第 2 步：自查

- 八节齐全？编号统一用中文数字 `一..八`？
- Gap 与问题分开了？
- 第⑤节是三行表？
- 第⑧节只给档、没越界打分？
- 每条结论都有锚点？
- 问答历史引的是原话？

### 第 3 步：落盘

- 位置：论文自己的目录下
- 命名：`<短名>_单篇总结_<日期>.md`
- **不覆盖**上游产物

### 第 4 步：更新判断（不可省略）

产出后立刻做三件事：

1. 判断这次是否暴露了某种**字段缺失**（某个该有的信息没地方记）
2. 如果发现了，评估补全历史总结的成本
3. **只出建议，不动手改历史文件**

清查范围是**全部轮次**，依据 `ledger/registry.md`（全量索引）。读登记册，不读案例库——案例库只有"已评过分"的行，读不到"还没评过的"。

输出格式：

```
【历史总结更新建议】
- 本次暴露的问题：<有/无，具体是什么>
- 清查范围：全部轮次
- 受影响论文（按轮次分组）：<清单>
- 缺口类型：<缺失字段>
- 更新成本：低/中/高（材料现成 还是 需重读原文）
- 建议：更新 / 不更新 / 等下次一起
- 决定权：用户
```

**只有登记册的「最近检查」列可以自动改。** 历史总结文件是用户的资产，要改先问。

## 七、常见误用

| 误用 | 后果 |
|---|---|
| 用户还没读完就跑 | 第①节空、第⑧节是 AI 的判断，整份文件失去意义 |
| Gap 和问题混在一节 | 引用时分不清"没做"还是"做错" |
| 亮点复述论文自称的贡献 | 与"我的评估"混淆；自称的创新常常站不住 |
| 第⑤节写成摘要 | 引用口径无法复用，等于没写 |
| 本节就打五维分 | 与 05 的尺度打架 |
| 不问就改历史文件 | 破坏用户的历史资产 |
| 第三方答疑不标来源 | 读者无法判断可靠性，错数值无人拦 |
| 多份转录只留最全的一份 | 丢掉前一份独有的问题 |
| 未核实的数字写进结论段 | 错误数字进入正式记录 |
