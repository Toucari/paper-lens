# 05 · 五维评分与跨篇比较

目标：让不同论文、不同时间打的分**可比、可累积、可校准**。

朴素做法（"这篇 8 分，那篇 7 分"）撑不过十篇就会乱：没有锚点、没有校准、换个时间打的分和前一批对不上。这一节解决的就是这个问题。

**前置**：用户已读完 + `04-summarize.md` 的八节总结已产出。八节总结的 §六（问题）和 §四（Gap）就是本阶段的取证材料，不必回原文重复劳动。

---

## 一、三条铁律

1. **按实际价值评，不按方向评。** 与你的研究方向贴合度是**软约束**，只在最后"与我的关系"单列一行，**不计入五维**。
2. **工具价值与结论价值分开记。** 同一篇可以是"模块的来源"同时是"结论的靶子"。禁止合并成"这篇不错 / 一般"。
3. **每一分都要有锚点。** 落到式号 / 表号 / 代码 `文件:行号` / 可复现的数值对比。禁止"质量一般""结果存疑"这类表述。

---

## 二、五个维度

| 维度 | 权重 | 看什么 | 典型扣分信号 |
|---|---|---|---|
| **方法创新** | 20% | 有没有真新的东西，还是组合已有模块 | 立论未实证（用模型输出论证模型符合先验＝循环论证）；核心卖点无针对性实验 |
| **实证可信度** | 25% | 对照是否干净、数字是否可复现、有无评测越界 | 测试集调参 / 测试集选 checkpoint；消融同时动多个变量；基线数字全靠引用没重跑；无显著性检验 |
| **可复现性** | 20% | 权重是否开源、单卡能否跑、预训练成本是否可及 | 预训练成本超常规算力；官方脚本有 bug；只放小模型不放主模型 |
| **可搬运性** | 20% | 有哪些模块能直接拿走（接口、位置编码、损失设计、训练配方） | 依赖论文特有数据条件才成立 |
| **严谨与诚实** | 15% | 内部一致性、是否自曝弱点、claim 与证据是否匹配 | 内部数值矛盾；论文 vs 代码不符；结论与数据方向相反；claim 超出证据 |

逐档锚点见 `assets/scoring-anchors.md`。**打分时逐维对照锚点表，不要凭印象给分。**

加权总分 = Σ(得分 × 权重)，保留两位小数。

**分档线**：≥ 4.0 → **A**；3.3–3.9 → **B**；< 3.3 → **C**。

---

## 三、最容易打错的一维：实证可信度

25% 的权重，且最容易被"结果好"误导。**这一维问的不是"结果好不好"，而是"这个结果能不能当证据"。**

打分前逐条过：

| # | 检查项 | 命中则 |
|---|---|---|
| 1 | 超参 / checkpoint 是否在测试集上选 | 上限 2 分 |
| 2 | 交叉验证的测试集是否每折不同 | 测试集固定 → 上限 3 分 |
| 3 | 划分单位是被试 / 受试者，还是样本 / trial | 被试内划分或未声明 → 上限 3 分 |
| 4 | 消融是否同时改动多个变量 | 命中 → 上限 3 分 |
| 5 | 基线数字是自己跑的还是引用原论文 | 全部引用 → 上限 3 分 |
| 6 | 有无显著性检验 / 置信区间 | 只有 mean±std → 上限 4 分 |
| 7 | 预训练语料与下游评测集是否隔离、如何声明 | 未声明 → 上限 3 分 |
| 8 | 对比的是最强基线还是最弱基线 | 只与弱基线比 → 上限 3 分 |

**第 7 项最隐蔽也最致命**：一个模型在 A 数据集上预训练，又在 A 数据集上评测，数字再高也不构成泛化证据。同类问题见 `06-leakage-audit.md`。

## 四、执行流程

### 第 0 步：校准（每次必做，成本很低）

1. 读 `ledger/registry.md` 的「最近检查」列，看有无遗留判断项
2. 读 `ledger/case-library.md` **最后 10 条**，用已评过的论文锚定尺度
3. 案例库不足 10 条就照常评，并记一条"样本不足"

**校准不是形式主义**：人的打分尺度会随心情和时间漂移，读 10 条历史分数能把尺度拉回来。

### 第 1 步：取证（三层，上游优先）

| 层 | 来源 | 用途 |
|---|---|---|
| 1（首选） | 同篇八节总结 | §六问题 + §四Gap 就是现成材料 |
| 2 | 论文原文 | 上游缺料或怀疑有误时才回原文 |
| 3 | 官方代码 | 核实"论文 vs 代码"差异 |

与上游结论分歧时**必须显式说明理由**——八节总结是权威底本。缺哪项就在报告里标"未经核实"。

取证清单：

| 要取什么 | 去哪取 |
|---|---|
| 主结果 + **最强基线**数值 | 正文表格（或上游 §二） |
| 消融是否控制变量（是否从头重训、参数量是否对齐） | 附录 + 代码 |
| 评测划分单位（被试 / 被试内 / 样本级）是否声明 | 实验设置节 + 切分代码 |
| 论文声明 vs 代码实现差异 | 逐文件核对仓库 |
| 权重是否开源、预训练算力 | README / 附录超参表 |
| **论文内部**是否有数值矛盾 | 全文交叉核对（表 vs 正文 vs 附录） |

### 第 2 步：打分

逐维给 1–5 整数分。**遇到框架没覆盖的情况，仍按现有五维打分，在报告末尾单列"框架外观察"**——不要临时改框架，改框架走第 4 步。

### 第 3 步：输出

**单篇模式**（默认）：只出五维表 + 档位 + 回写行。**不排序、不画散点。**

```markdown
## 评估口径
（一句话说明权重；若某维的可信度来自专门的审计，注明）

| 维度 | 权重 | 得分 | 证据锚点 |
|---|---|---|---|
| 方法创新 | 20% | | |
| 实证可信度 | 25% | | |
| 可复现性 | 20% | | |
| 可搬运性 | 20% | | |
| 严谨与诚实 | 15% | | |
| **加权总分** | | **x.xx** | **档：A/B/C** |

## 真价值 / 扣分
- 真价值：（带锚点）
- 扣分：（带锚点）
- 与我的关系：（方向贴合度，单列，不计分）

## 三类引用口径
| 用途 | 可以引 | 不要引 |
|---|---|---|
| 引结论 | | |
| 搬模块 | | |
| 当靶子 | | |
```

**批次模式**：总表 + 排序 + 双轴散点。逐篇点评改为**指针**，指回各单篇 §八——**不复制**，避免双份评级漂移。

```markdown
## 评估口径
## 总表
| 排名 | 论文 | 方法创新 | 实证可信 | 可复现 | 可搬运 | 严谨诚实 | 总分 | 档 |
## 逐篇点评
（每篇一句话 + 指向 `<短名>_单篇总结_<日期>.md` §八 的链接，不复制内容）
## 价值定位
（双轴散点：横轴 = 实证可信度，纵轴 = 可搬运性，取原始 1–5 分）
```

**双轴的意义**：两轴相互独立。"可信"与"可用"不重合是常态——工具性极强的论文常常评测粗糙。散点能一眼看出四个象限里各有哪些论文，这比一维排名有用得多。

### 第 4 步：回写（不可省略）

1. **写案例库**：每篇追加或更新一行到 `ledger/case-library.md`
   - 去重键 = **短名 + venue**；重评**覆盖旧行**并标 `[重评 <日期>]`，不追加
2. **写登记册**：更新 `ledger/registry.md` 对应行的评级 / 总分 / 合规 / **最近检查**
   - **只有「最近检查」列可以自动改**
3. **历史重算判断**：若改了权重 / 锚点 / 分档线，列出受影响的旧条目并出建议
4. 发现框架缺陷（缺维度、锚点失真、分档线不合理）→ 改 `assets/scoring-anchors.md`，并在 `ledger/changelog.md` 留痕
5. **回写完才给最终回复。不回写的评估等于白做。**

重算建议格式：

```
【历史打分重算建议】
- 本次变更：权重/锚点/分档线 有无改动
- 清查范围：全部轮次
- 受影响的论文（按轮次分组）：<清单>
- 影响程度：<总分变化估计>
- 建议：重算 / 不重算 / 等下次一起
- 决定权：用户
```

## 五、两个账本，不能合并

| 文件 | 作用 | 解决什么 |
|---|---|---|
| `ledger/registry.md` | **全量索引**，每篇一行 | 解决"漏" |
| `ledger/case-library.md` | **评分锚点**，只存已打分的行 | 解决"尺度漂移" |

**为什么不能合并**：案例库只有评过分的行，用它做全量清查会读不到"还没评过的论文"——而"还没评"的恰恰最需要被找出来。

两个账本的表头与字段说明分别在 `assets/registry-template.md` 和 `assets/case-library-template.md`。`plens.py init` 会生成精简版；**要带完整字段说明就用模板文件覆盖一次**（第一次建库时建议这么做，否则半年后你会忘记某列该填什么）。

案例库一行格式（保持单行，便于低成本 grep）：

```
| 短名 | venue 年份 | 创新 | 实证 | 复现 | 搬运 | 诚实 | 总分 | 档 | 一句话理由 | 关键证据锚点 |
```

**冗余保护**：超过 60 行后，把早期条目压成"分数段统计"（如"2026 上半年 20 篇：A 3 / B 12 / C 5"），只保留 A 档与 C 档的完整行——这两档是校准的锚，中间档可以合并。

---

## 六、校准的三条规则

1. 打分前读案例库最后 10 条，确认尺度一致
2. 分数落在分档线 ±0.15 内时，在点评里显式说明"为什么跨了这条线"
3. **若"按锚点打分但结果明显失真"，改锚点，不改分数** —— 分数是锚点的产物，改分数等于绕过标准

---

## 七、常见误用

| 误用 | 后果 |
|---|---|
| 用户没读完 / 八节未出就评分 | 取证无源，评级无据 |
| 把方向贴合度算进五维 | 评分被研究方向绑架 |
| 只给总分不给锚点 | 分数无法复用、无法校准 |
| 用"是不是 SOTA"代替"实证可信" | 把结果大小误当证据质量 |
| 评估完不回写 | 下次无法校准，框架停止进化 |
| 一篇只给一个定性词 | 丢掉"工具可用但结论不可引"这类关键区分 |
| 批次里重写逐篇点评 | 与单篇 §八 形成双份评级，必然漂移 |
| 清查范围只写"上一轮" | 轮次一多必漏 |
| 重评后追加新行 | 校准时重复计权 |
