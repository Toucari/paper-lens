# 06 · 数据泄漏审计

**这一节回答一个问题：论文报的那个分数，能不能当作"模型真的学到了这件事"的证据？**

不能的话，分数再高也只是数字。审计结论直接折算进 `05-evaluate.md` 的「实证可信度」维度。

**什么时候跑**：被评论文属于"用信号预测内容"这类任务（解码、跨模态对齐、生成、检索），或者你怀疑分数虚高。纯理论 / 纯架构改进的论文可以跳过。

---

## 一、为什么单看分数不够

一个"输入 → 内容"的模型，得分高可能来自四条完全不同的路径：

| 路径 | 是否构成证据 |
|---|---|
| 真的从输入里解出了内容 | ✅ 是 |
| 记住了训练时见过的样本（数据泄漏） | ❌ 否 |
| 靠数据集的统计捷径（类别先验、长度、速率） | ❌ 否 |
| 评测协议放松了（teacher forcing、划分错误） | ❌ 否 |

**审计的目的就是把后三条排除掉。** 排除不掉，就只能写"分数不能作为解码证据"。

---

## 二、通用五问（任何领域都问）

### 问 1：划分单位是什么？

| 划分方式 | 强度 | 说明 |
|---|---|---|
| **跨被试 / 跨受试者（LOSO）** | 最强 | 测试对象从未出现在训练中 |
| 跨会话 / 跨录制 | 中 | 同一对象，不同时间 |
| **被试内随机划分** | 最弱 | 同一对象的样本同时出现在训练与测试 |

**论文没写划分单位，本身就是扣分项。** 但凡涉及"个体差异"的任务，被试内划分的分数不能外推到新对象。

**危险信号**：正文说"跨被试"，但代码里 `train_test_split` 没有按被试分组。这种情况必须看代码，不能只看文字。

### 问 2：有没有零信号地板？

做法：把输入替换成**不含目标信息**的版本，重跑评测。

| 替代输入 | 期望 |
|---|---|
| 高斯噪声 | 分数掉到随机水平 |
| 全零 / 常数 | 分数掉到随机水平 |
| **另一个样本的输入**（打乱配对） | 分数掉到随机水平 |
| 只有长度/速率信息 | 分数不应显著高于随机 |

**如果打乱配对后分数只掉一点点，说明模型学到的主要不是输入与内容的对应关系。**

零信号地板是**最便宜、最能暴露问题**的对照，也是最常被省略的。论文没做，你可以自己补——通常几行代码。

### 问 3：预训练数据与评测集是否隔离？

这是**跨论文**的问题，单看一篇看不出来。

检查顺序：

1. 这篇的预训练语料清单里，有没有评测用到的数据集？
2. 如果有，有没有**明确声明剔除下游评测部分**？
3. 如果没有声明 → 上限 3 分（实证可信度）
4. **再查一层**：这篇论文的基线，是不是另一篇论文的预训练数据？

第 4 条最容易漏。真实情形：论文 A 用一个数据集 D 做预训练，论文 B 拿 A 当基线、并在 D 上评测。两边各自都声明了自己用了什么，**但合起来构成泄漏**。审计时要顺着基线往上游查一层。

### 问 4：评测指标是否被"选择"过？

| 现象 | 问题 |
|---|---|
| 只报 3 个指标里最好的那个 | 选择性报告 |
| 多个数据集里只报涨的 | 同上 |
| 主指标降、辅助指标涨，但结论说"提升了" | claim 与数据方向不符 |
| 超参在测试集上选 | 直接上限 2 分 |

**看消融/主表时，先找"哪个数字是降的"**，找不到才说明可能是全面的——而不是反过来。

### 问 5：同一配置跑了多少次？

只有 `mean ± std` 而没有显著性检验，小差异无法判断。

判断规则（粗略）：两组分数差小于合并标准误的 2 倍时，**只能说"无法区分"，不能说"优于"。

计算方式：

```
合并标准误 ≈ sqrt( std_A²/n_A + std_B²/n_B )
```

差值与合并标准误的比值 ≈ 1 → 噪声内；≥ 2 → 可以说"有显著趋势"（仍需注明未做正式检验）。

**不要只看点估计就宣布某个配置最优。** 真实教训：两个配置 0.5758 vs 0.5337，看着差 0.04，算下来只有 1.2 个标准误——完全在噪声内。

**另一个陷阱**：同一张消融表，不同指标的最优配置可能不同（Kappa 峰在 2 层，Balanced Accuracy 峰在 6 层）。别只挑一个指标宣布"最优配置"。

## 三、领域检查表（按 `profile.md` 的领域填）

不同任务的泄漏方式不同。以下是**信号→内容**类任务的清单，其他领域请参照结构自建。

### 例：生理信号 → 文本 / 语音解码

| 检查项 | 为什么是泄漏 | 怎么查 |
|---|---|---|
| **呈现速率 / 采样节奏是否对齐** | 训练与测试的呈现速度不同时，模型可能只学到节奏特征而非内容 | 看实验设置里的呈现参数；train/test 是否一致 |
| **是否跨句 / 跨词划分** | 测试句在训练中出现过 → 背下来即可 | 找"unseen sentence / unseen word"评测；没有就是缺口 |
| **生成是否用 teacher forcing** | 每步喂真实前词，评的是"给定正确答案能否选对下一个词" | 看解码描述；自回归生成必须报自由生成结果 |
| **句子集合是否重叠** | 同一批句子配对不同的信号 → 句级泄漏 | 看数据集划分脚本 |
| **标签泄漏** | 预处理里用了全量统计量（如全局归一化参数） | 看预处理代码是否 fit 在全量数据上 |
| **通道/导联选择是否用了测试集信息** | 特征选择若在全体数据上做，等于偷看测试集 | 看特征选择是否只在 train 上做 |
| **同一受试者的多次录制是否同时进 train/test** | 个体的稳定特征可被记住 | 看划分单位 |

**通用规律**：任何"在全体数据上算一个参数，再用它处理单条样本"的操作，都是潜在泄漏（归一化、PCA、特征选择、聚类中心）。

### 例：其他领域怎么建表

问三个问题就能列出你的清单：

1. 这个任务的"内容"以什么形式存在？（句子、类别、事件、时间点）
2. 训练集和测试集在**哪个维度上重叠**会造成泄漏？（同一个体、同一句话、同一场景、同一时间段）
3. 有哪些**预处理/统计量**是用全量数据算的？

## 四、判决：三档

| 档 | 条件 | 对分数的主张 |
|---|---|---|
| 🟢 **可作证据** | 划分单位明确且严格；有零信号地板且分数掉到随机；生成任务是自由生成；未见句/词有单独评测；预训练与评测已隔离并声明 | 可以说"模型从输入中解出了该内容" |
| 🟡 **可作参考** | 有 1–2 项缺失或弱化，但主结论方向不受影响 | 必须加限定语："在该数据集、该划分下" |
| 🔴 **不可作证据** | 划分单位未声明或被试内；无任何负对照；生成靠 teacher forcing；预训练含评测数据未剔除 | 只能说"在该设置下拟合出了高分"，不能说"解出了内容" |

### 折算进实证可信度

| 审计结论 | 实证可信度得分 |
|---|---|
| 🟢 + 其他项干净 | 4–5 |
| 🟡 | 3–4 |
| 🔴 | **上限 3**；若同时存在测试集调参 → **上限 2** |

## 六、写审计结论的纪律

1. **只说审计能支撑的话。** 审计出"划分未声明"，结论就是"划分未声明"，不是"数据一定泄漏"——后者是推断，要标"推断"。
2. **证据要能指回去。** 每行落到节号 / 表号 / 代码行。指不回去的写成"未核实"。
3. **不替论文补它没做的实验。** 缺什么就写缺什么，不要假设"他们大概做了"。
4. **区分"论文的问题"和"领域的问题"。** 整个领域都没有零信号地板，是领域的缺口（进 §四 Gap），不是这一篇的缺陷（进 §六）。

## 七、常见误判

| 误判 | 纠正 |
|---|---|
| 分数接近随机水平 → 一定是泄漏 | 也可能就是没学到。要看零信号地板，不看绝对分数 |
| 划分写了"cross-subject" → 一定干净 | 看代码。文字与实现不一致很常见 |
| 有方差就够了 | 方差 ≠ 显著性检验，但比没有好 |
| 预训练数据里没提这个数据集 → 没问题 | 基线可能是别的论文的预训练数据，往上查一层 |
| 附录没写 = 没做 | 先用 `toc` 确认附录有哪些节，别漏读 |
