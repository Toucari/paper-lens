# 全局约定

任何档位开始前读一次。这里定义的是**所有阶段共用的东西**，各阶段的细节在 `01`–`06`。

---

## 一、两个根目录，不要混

| 名称 | 是什么 | 谁决定 |
|---|---|---|
| **skill 目录** | 本仓库所在目录，放 `SKILL.md` / `references/` / `scripts/` | 克隆到哪就是哪，只读 |
| **库根目录 `PL_ROOT`** | 你的论文收藏根目录，放 `papers/` / `rounds/` / `ledger/` | `profile.md` 里配置 |

写产物、建目录、抽文本，**全部落在 `PL_ROOT` 下**，绝不写进 skill 目录。

`profile.md` 位于 `PL_ROOT` 下，是唯一需要人工维护的配置文件。首次使用见 `setup.md`。

---

## 二、库目录结构

```
$PL_ROOT/
├── profile.md                      ← 研究画像与配置（你维护）
├── papers/
│   └── <VENUE 年份>/               ← 如 "ICLR 2025"；期刊只用刊名，不带年份
│       └── <论文标题>/              ← 去掉冒号与问号
│           ├── <arxiv-id>v<n>.pdf
│           ├── info.md
│           ├── figures/figNN.png
│           ├── <短名>_速读卡_<日期>.md
│           ├── <短名>_中文精读.md
│           ├── <短名>_精读_图文版.html
│           └── <短名>_单篇总结_<日期>.md
├── rounds/
│   └── <日期> <轮次名>.md
└── ledger/
    ├── registry.md                  ← 全量登记册
    └── case-library.md              ← 评分锚点
```

`profile.md` 里的 `topic_grouping` 可以把 `papers/` 再分一层主题子目录（如按研究方向分组）。**没有配置就平铺**，不要自己发明层级。

## 三、命名规则

| 对象 | 规则 | 例 |
|---|---|---|
| 短名 `<short>` | 论文常用缩写，全库统一；出现歧义时用 `会议缩写-短名` | `BERT`、`ViT` |
| 论文目录名 | **原题**，去掉 `:` 和 `?`（Windows 不允许），保留其余大小写与连字符 | `Meta-Learning an In-context Transformer Model of Human Higher Visual Cortex` |
| venue 目录 | `会议名 年份`；期刊只写刊名 | `NeurIPS 2025`、`TNNLS` |
| 日期后缀 | `YYYY-MM-DD`，**用 `date +%F` 取** | `2026-10-21` |
| PDF 文件名 | `<arxiv-id>v<n>.pdf`；无 arXiv 版用描述性名 | `2412.07236v6.pdf` |

**日期必须从命令行取，不要用对话上下文里的时间。** 上下文日期可能过期（实测差过几天）。

```bash
date +%F          # 2026-10-21
```

## 四、四件产物，互不替代

这四件东西解决不同问题，**不能拿一件顶另一件**：

| 产物 | 解决的问题 | 谁读 |
|---|---|---|
| `<短名>_中文精读.md` | 逐节读懂：符号、维度、数据流、公式读法 | 用户本人精读 |
| `<短名>_精读_图文版.html` | 同上，但带图、可导航、适合长文 | 用户本人精读 |
| `<短名>_单篇总结_<日期>.md` | 八节结构化归档：Gap / 问题 / 引用口径 / 评级 | 未来的自己、合作者 |
| `<短名>_速读卡_<日期>.md` | 15 分钟内决定"要不要读" | 排优先级时的自己 |

产物顺序有依赖：**精读（第 3 阶段）→ 用户读完 → 八节总结（第 4 阶段）→ 五维评分（第 5 阶段）**。倒过来做会产生"AI 自述式总结"。

## 五、文本与编码

- 所有文件 **UTF-8 无 BOM**，换行 `\n`。
- Windows 控制台常是 GBK：**脚本只打印 ASCII**，中文结果写进文件，不要 `print` 中文或数学符号（会乱码或抛异常）。
- 抽出的全文文本统一放 `$PL_ROOT/papers/.../` 下的临时文件，或系统临时目录；**不要留在 skill 目录**。
- 临时文件清理用 `mv` 改名或移入 `_trash_<日期>/`，**不要 `rm`**——用户的数据由用户自己删。

---

## 六、与他人协作时的规则

如果这条流水线是多人共用一个库：

- 每篇论文的**评级以单篇总结的 §八 为权威**；轮次总结、批次表只放指针，不复制评级（复制必然漂移）。
- 登记册的「最近检查」列是工作台账，可自动更新；**其他列与历史总结文件，改动前要征得同意**。
- 同一篇论文重评时**覆盖旧行**并标 `[重评 <日期>]`，不要追加（追加会让校准时重复计权）。

## 七、失败时的默认动作

| 情况 | 默认动作 |
|---|---|
| PDF 抽不出文本（扫描版） | 明确告知，建议换带文本层的版本；**不要用 OCR 猜数字** |
| 找不到 arXiv 版 | 把 OpenReview / 会议 proceedings 链接给用户，由人工取；不要静默跳过 |
| 论文内部数值矛盾 | 原样记录两处位置，不调和，交用户判断 |
| 表格抽不全（附录常见） | 标"该表需人工核对 PDF"，不要凭图像猜 |
| 数值核不到 | 标 ⚠️ 未经核实，且**不得进入结论性段落** |
