# Case library — 评分锚点

> **唯一作用**：打分前校准尺度。人的评分会随时间和心情漂移，读最后 10 行能把尺度拉回来。
>
> **与 registry 的分工**：本文件 = 分数锚点（只存**已打分**的行）；`registry.md` = 全量索引（含未打分的行）。
> **两者不得合并**——案例库读不到"还没评过的论文"，用它做全量清查必漏。

## 写入规则

- **去重键 = 短名 + venue**。同一篇重评时**覆盖旧行**，标 `[重评 YYYY-MM-DD]`，**不追加**（追加会让校准时重复计权）。
- 每次评估后必须回写。**不回写的评估等于白做。**
- 超过 60 行后压缩：早期条目合并成"分数段统计"，只保留 A 档与 C 档完整行（这两档是校准锚）。

## 字段

| 列 | 填什么 |
|---|---|
| novelty / evidence / repro / reuse / honesty | 五维原始分，1–5 整数 |
| total | 加权总分，两位小数 |
| grade | A（≥4.0）/ B（3.3–3.9）/ C（<3.3） |
| one-line reason | 一句话说清"为什么是这个档"，不要写"质量不错" |
| key anchor | 最关键的那条证据，带表号/式号/代码行 |
