# 六维评分锚点

> 用途：给 `references/05-evaluate.md` 提供 1–5 分的判定标准。打分时逐维对照本表，禁止凭印象给分。
> 修改本文件时，同步在 `ledger/changelog.md` 记一条变更——**改锚点会移动历史分数**，影响比改单篇分数大得多。

---

## 口径版本（先看这一节）

| 版本 | 维度 | 状态 |
|---|---|---|
| **v1** | 五维：创新 20 / 实证 25 / 复现 20 / 搬运 20 / 诚实 15 | 已废弃 |
| **v2** | 六维：创新 15 / 实证 25 / 复现 15 / 搬运 20 / 诚实 10 / **训练开销 15** | 现行（2026-11 起） |

**v1 → v2 改了什么、为什么**

v1 的「可复现性 / 成本」把两件不同的事压在一维里：**"代码能不能跑出同样的数"** 和 **"要多少张卡才跑得动"**。后果是同一篇论文在两件完全无关的事上扣同一个分——一个代码齐全但需要 64 卡的工作，和一个代码有 bug 但单卡能跑的工作，可能都得 3 分。

拆开之后，**大算力不再伪装成"不可复现"**，而是显式记在开销维上。这对算力有限的读者尤其重要：他要的正是"哪些论文我跑得起"这个信息，压在一维里就看不见了。

其余五维按比例让出 15 个百分点：创新 20→15、复现 20→15、诚实 15→10。**实证 25 与搬运 20 不动**——这两维对"结论能不能引、模块能不能拿"的区分度最高，压缩它们会丢掉最关键的判断。

> **⛔ v1 与 v2 的分数不可直接比较。** 历史分数在登记册里一律标 `v1`，不要拿它和 v2 排序。要不要重算由用户决定，见 `05-evaluate.md` 第 4 步。

**权重可覆盖**：默认权重写死在本文档，但用户可以在 `profile.md` 的 `scoring.weights` 里改成自己的口径。改权重等于换口径版本，必须记 `ledger/changelog.md` 并触发历史重算判断。

## 一、方法创新（权重 15%）

| 分 | 锚点 |
|---|---|
| **5** | 提出新的问题设定或新的统一范式，且该设计有消融证明其有效性（消融支持，不是作者自述） |
| **4** | 有原创模块（非简单搬运），但整体框架沿用已有范式 |
| **3** | 组合已有模块解决新问题，无原创模块 |
| **2** | 主要是工程适配，或是对已发表工作的规模扩展 |
| **1** | 复现 / 微调已有工作，无方法贡献 |

**判「无原创模块」的依据**：模块能在参考文献里找到直接来源（如"沿用某编解码器的编码器""沿用 MAE 的掩码策略"）。
**扣分到 3 以下的常见原因**：立论（motivation）从未被实证——例如用模型自己学到的注意力去论证"模型符合数据先验"。

---

## 二、实证可信度（权重 25%）

| 分 | 锚点 |
|---|---|
| **5** | 对照控制变量（每个变体从头训练 + 参数量对齐 + 同报算力）；划分单位与粒度声明清楚；无任何评测越界；论文数字与代码一致 |
| **4** | 对照基本干净，有 1 处小瑕疵（如消融只覆盖部分数据集） |
| **3** | 主结果可信，但存在 1 处结构性瑕疵（基线数字靠引用未重跑 / 无显著性检验 / 只报一种划分） |
| **2** | 存在评测越界（在测试集上调超参或选 checkpoint），或划分粒度未声明 |
| **1** | 核心 claim 与数据方向相反，或核心指标全面落后于所对比的前作 |

**明细检查清单**（打分前逐条过）：

| # | 检查项 | 命中则扣分 |
|---|---|---|
| 1 | 超参 / checkpoint 是否在测试集上选 | 直接上限 2 分 |
| 2 | 交叉验证的测试集是否每折不同 | 测试集固定 → 上限 3 分 |
| 3 | 划分单位是个体 / 受试者，还是样本 / trial | 个体内划分或未声明 → 上限 3 分 |
| 4 | 消融是否同时改动多个变量 | 命中 → 上限 3 分 |
| 5 | 基线数字是自己跑的还是引用原论文 | 全部引用 → 上限 3 分 |
| 6 | 有无显著性检验 / 置信区间 | 只有 mean±std → 上限 4 分 |
| 7 | 预训练语料与下游评测集是否隔离、隔离粒度如何声明 | 未声明 → 上限 3 分 |
| 8 | 最强基线（而非最弱基线）的对比是否给出 | 只与弱基线比 → 上限 3 分 |

## 三、可复现性（权重 15%）

> **只管"能不能跑出同样的数"，不管"要多少卡"**——算力门槛在第六节「训练开销」单列。同一件事不许在两维各扣一次。

| 分 | 锚点 |
|---|---|
| **5** | 权重 + 代码 + 训练脚本齐全，第三方按 README 能跑通全流程；预处理与数据划分脚本也在 |
| **4** | 代码开源且能跑，但缺 1 处关键环节（如预处理脚本、划分文件、词表/码本） |
| **3** | 代码开源但有坑（依赖版本锁死 / 关键超参与论文不符 / 只放部分脚本），需读码才能复现 |
| **2** | 部分开源 / 官方脚本有 bug / 只提供小模型权重而主结果用大模型 |
| **1** | 未开源，或提供的资源无法复现论文主张 |

**注意**：① "论文说 16 卡、脚本写 8 卡"这类**不一致**归「严谨与诚实」，不重复扣本维；② **"要 8 张卡才跑得动"归「训练开销」**，本维不再因此扣分。

---

## 四、可搬运性 / 工具价值（权重 20%）

| 分 | 锚点 |
|---|---|
| **5** | 提供**现成的、与主流下游兼容的接口**（如标准格式的 token / embedding），或提供可直接复用的通用组件（位置编码、损失函数、训练配方），且不依赖其私有数据 |
| **4** | 有 1–2 个可独立搬走的模块，但需少量适配 |
| **3** | 方法思路可借鉴，具体实现依赖论文特有条件 |
| **2** | 思路有价值，但落地依赖其私有数据或特定设置 |
| **1** | 无可搬运内容（纯结论型论文） |

**判「可搬运」的门槛**：搬走该模块后，**在别人的数据上仍成立**。仅在该论文的评测集上有效的技巧不算可搬运。

## 五、严谨与诚实（权重 10%）

| 分 | 锚点 |
|---|---|
| **5** | 内部无矛盾；**主动报告不利结果**；局限有量化说明（哪一格输、输多少） |
| **4** | 基本一致，有 1–2 处笔误或表述偏松（如把"补信息"称作 data augmentation） |
| **3** | 有内部数值矛盾或论文 vs 代码不符（≤3 处），但结论方向不受影响 |
| **2** | 多处内部矛盾，或 claim 明显超出证据 |
| **1** | 结论与数据方向相反且未说明 |

**加分信号（够两条即可上 5 分）**：
- 明确写出"去掉某组件后自己不如前作"这类不利数字；
- 明确交代基线数字来源（引用还是重跑）；
- 明确写出论文**没做**什么（缺哪个数据集、缺哪个对照）。

**扣分信号（够两条即降到 2 分）**：
- 同一指标在正文与附录数值不同；论文正文与代码实现不符；
- 同一引用编号指向两篇不同的论文；
- 结论句式比数据支持的强度更高（如数据是"打平"却写"优于"）。

> **成本披露不在本维计分**：报不报训练开销由第六节判分，本维只看"有没有自我批判"。

## 六、训练开销（权重 15%）

> **取数**：新篇取上游八节总结 §2.4 的六项；若库里有跨篇开销台账，历史篇取台账。**不许现场估、不许拿同类工作类比**。
> 上游完全没写且代码里也推不出 → 记 **N/A**，不进总分（见下）。

| 分 | 锚点 |
|---|---|
| **5** | 单卡 ≤1 天可复算，**六项全报**（卡型×卡数 / 显存 / 时长 / 参数量 / 数据量 / 复算可行性），代码与权重开源 |
| **4** | 单卡或双卡、≤3 天；或六项里只缺一项 |
| **3** | 2–8 卡且累计 ≤3 卡日；或 >8 卡但 ≤1 天；或六项里缺一项（如只有卡型没时长） |
| **2** | **累计 >3 卡日**（不论几张卡，例：4 卡 × 5 天 = 20 卡日）；或关键项缺两项以上；或参数量 ≥1B 且卡数未报 |
| **1** | 只有"用了什么卡"，时长/卡数/参数量均未报；或明显不可复算（千卡级、私有数据不可得） |
| **N/A** | 完全未提且代码也推不出 → **不计入总分**，`总分 = Σ(其余五维 × 权重) ÷ 0.85`，报告注明"开销维 N/A，已归一化" |

**三条防滥用规则**：

1. **口径以"可复算"为准，不以"数字大"为准**：8 卡跑 1 天的可复算性低于 1 卡跑 3 天，前者按 2 分档处理。
2. **数据获取门槛不单独扣分**：受控访问、需申请、需签协议在不少领域是通例，只写进备注，不因此降档。**但它会实质影响"我能不能跑"——这条要写进 §七 的成本列**。
3. **卡日优先于卡数**：4 卡 × 5 天 = 20 卡日，比 8 卡 × 1 天贵。报"用了 8 卡"不等于便宜。

## 七、分档与校准

| 总分 | 档 | 含义 |
|---|---|---|
| ≥ 4.0 | **A** | 证据可信且工具可用，可放心引用与复现 |
| 3.3–3.9 | **B** | 有明确价值，但需要在引用时加限定语 |
| < 3.3 | **C** | 工具或结论至少有一项不可用，仅作反面教材或纯工程件来源 |

**校准规则**：
1. 打分前读案例库最后 10 条，确认尺度一致。
2. 若某篇的分数落在分档线附近（±0.15），在点评里显式说明"跨档原因"。
3. 若发现"按锚点打分但结果明显失真"，**改锚点**而不是改分数，并记入日志。
